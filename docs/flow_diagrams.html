2. What happens on one turn (routing)

The safety rules run first. Only normal requests reach the LLM.

  C -->|hello / thanks| I[greeting / thanks

Say: "Eight of the nine routes use no LLM at all. That is deliberate: emergencies and confirmations must be predictable."

3. Booking, step by step (sequence)

The LLM stages a booking. Plain code commits it after a spoken yes.

sequenceDiagram
  autonumber
  actor C as Caller
  participant S as Speech (STT/TTS)
  participant G as LangGraph (nodes.py)
  participant L as LLM (Groq)
  participant T as Tools + checks (tools/)
  participant B as BookingService
  participant D as PostgreSQL
  C->>S: "Book a check-up Saturday morning"
  S->>G: text
  G->>L: instructions + last 6 turns + tool list
  L-->>G: tool request: check_availability("Saturday morning")
  G->>T: run tool
  T->>B: free slots?
  B->>D: confirmed bookings on that day
  D-->>B: rows
  B-->>T: free slots, as A / B / C
  T-->>G: exact words: "I have 9:00, 9:30 or 10:00"
  G->>S: code speaks the times
  S->>C: audio
  C->>S: "The second one, I'm Sam, 0770 900 123"
  S->>G: text
  G->>L: context hint: caller chose slot B
  L-->>G: tool request: book_appointment(name, slot B, phone)
  G->>T: run tool
  Note over T: Checks: slot B was offered?
phone number really said by the caller?
  T-->>G: staged in call state, not saved
  G->>S: read-back: "Sam, Saturday 9:30. Shall I book that?"
  S->>C: audio
  C->>S: "Yes"
  S->>G: text
  Note over G: rules.is_yes, then agent_confirm.
No LLM involved.
  G->>B: create booking
  B->>D: INSERT (unique index on confirmed start time)
  D-->>B: ok, or "time just taken"
  B-->>G: reference SD-000004
  G->>S: "You're booked. Reference SD-000004"
  S->>C: audio
  Note over T,D: Every tool call is also written to the tool_calls table with personal details masked
Say: "Even if the LLM is wrong, the worst it can do is propose something. Nothing is saved until the caller says yes, and the database refuses two bookings at the same time."

4. Knowledge search (RAG)

Top: built once by scripts/ingest.py. Bottom: used on every clinic question.

flowchart TD
  subgraph OFFLINE[Offline: python scripts/ingest.py]
    direction LR
    F1[data/raw/faq.md
the clinic's facts] --> F2[loader.py
read files]
    F2 --> F3[chunker.py
split at each ## heading
10 chunks]
    F3 --> F4[embedder.py
MiniLM: text to vector]
    F4 --> F5[store.py
save index.json + meta.json
with a fingerprint]
  end
  subgraph ONLINE[Online: every clinic question]
    direction TB
    Q1[Caller: How much is a check-up?] --> Q2[LLM calls get_clinic_info]
    Q2 --> Q3[retriever.py
embed the question]
    Q3 --> Q4[compare with chunk vectors
cosine similarity]
    Q4 --> Q5{best score at least 0.35?}
    Q5 -->|no| Q6[I don't have that information
logged as unanswered question]
    Q5 -->|yes| Q7[top 2 chunks go to the LLM]
    Q7 --> Q8[LLM phrases the answer
from those chunks only]
  end
  F5 -.loaded at startup.-> Q3
  F5 -.if documents changed, fingerprint differs:
re-embed at start.-> Q3
Say: "The threshold is what stops confident wrong answers. Real clinic questions score about 0.39 and up; questions like weather score about 0.30 and below."

5. Safety layers (defence in depth)

Each layer assumes the one before it can fail.

flowchart TD
  L1[Layer 1: emergency and advice rules
run BEFORE the LLM, fixed replies] --> L2
  L2[Layer 2: LLM only chooses tools
it has no database access] --> L3
  L3[Layer 3: argument checks, tools/base.py
slot must have been offered
booking id must be known
phone must have been said by the caller] --> L4
  L4[Layer 4: output check, guardrails.py
LLM may not state a time or price itself
tools return the exact words] --> L5
  L5[Layer 5: stage then commit
tools only stage; a spoken yes, detected by code, commits] --> L6
  L6[Layer 6: database
unique index on confirmed start time
cannot double book even in a race] --> L7
  L7[Layer 7: audit and monitoring
tool_calls table with masked arguments
metrics, JSON logs per call]
Say: "No single layer is trusted. Layers 3 to 6 mean a wrong LLM answer cannot become a wrong booking."
